# swarm → team：扇出分诊 + 深挖回执

> [!important] 自主判断，不等用户点名
> 判断与选工具是**你**的活。只要出现「≥3 个同类独立条目」或「先扫一遍再决定深挖哪些」，就默认走本流程。
> 反面：单一任务、或本来就需要工具才能做的活（且 swarm 在默认路径 A），不要硬套，直接干，必要时 spawn 一个队友。

**一条流水线，四个阶段 + 一个续跑分支。便宜的先铺开，贵的只用在被证据点名的条目上。**

## 0. 先选对工具（选错整条流水线白跑）

| 单条工作在性质上属于… | 用什么 | 原因 |
| --- | --- | --- |
| 只靠模型知识/给定文本就能做完（分诊、摘要、初筛、改写、翻译、命名、清单） | **agent_swarm（默认）** | 子任务 = 一次 `llm.stream`：**无工具、无文件访问**、便宜、可高并发 |
| **必须读文件/跑命令/查网页才能定论**，但条目彼此独立 | **agent_swarm + 路径 B**（实例配了 `subagentProvider: spawn`） | 子任务 = 完整宿主 subagent：**有工具、能多轮**，比派队友轻 |
| 要反复追问、跨条目协调、或要改文件 | **agent team** | 队友是完整 agent：有会话、有工具、能被反复触达 |
| 需要"先扫一遍再深挖" | **本技能：swarm → 分诊 → team** | 用便宜的过滤掉大部分，只给贵的条目付钱 |

### 红线（按当前配置分叉，别背错）

- **路径 A（默认，没配 `subagentProvider`）**：需要读文件、跑命令、验证事实的活**不许**塞进 items —— 它只会凭空编。
- **路径 B（配了 `subagentProvider`）**：这些活**可以**交给 items，但模板里要**显式要求它用工具**：`用文件工具打开 {{item.path}}，只回答……，不要解释`。实测过：子代理会真的读文件再作答。
- **不确定当前哪条路径**：看返回值的 `path` 字段（`llm` / `subagent`）与 `pathReason`；若实例配了 `subagentProvider: auto`，**不用你操心**——插件已按条目/模板自动选好路径。仍不放心时先用一个条目探一下，**不要默认自己能读文件**（固定路径 A 时无工具）。

## 1. 阶段 1 · 扇出（`agent_swarm`）

- **优先用结构化条目**：`items: [{path: 'src/a.ts', focus: '回归'}, …]` + `prompt_template: '审查 {{item.path}}，关注 {{item.focus}}'`，比把字段拼进字符串稳。
- **模板必须钉死输出格式**（`只回答 X，不要解释`），否则阶段 2 分诊没法做。
- **批量要克制**：单批建议 ≤30 条，条目多就先切批；模长用 `maxPromptChars` 兜底，正文用 `maxBodyChars` 截断（2000–4000）。
- **条目必须互不依赖**：有前后依赖的活不要放进同一批。
- **长批先看开跑预检**：实例开了 `progressLog` 时，批量会在**校验通过、零子任务启动**的那一刻先写一行 `starting N subtasks (first wave X, +1 every Yms, …)`。看到这行说明前置换校验已过、马上开始烧钱；没看到就说明**前置校验没过、零子任务启动**（去读错误文案改参，别怀疑它卡了）。
- **成本看结构化字段**：工具返回值是对象（`text` + `counts` + `items[]` + `usage`）。**`usage` 是 token 用量**（条目级 + 整批合计），只在结构化值里、人读文本不含 —— 想知道这批花了多少、要不要再扇一轮，读它，别靠猜。
- **每条带 `reason`**：失败条目有机器可判的失败原因（见 §5 表），据此决定动作，不要一律重跑。

## 1.5 阶段 1.5 · 续跑未完成项（别整批重跑）

| 情况 | 做法 |
| --- | --- |
| 路径 B 某条 `outcome≠completed`，或你想让它接着往下做 | 回执每条带 `agent=<子会话 id>`；**用保留键续跑**：`items: [{agent: '<那个 id>', path: '…'}]`（**单条也合法**）→ 子会话接着上轮跑、上下文不断，汇总标 `resumed=true` 且 `agent=` 与上轮**同一个 id** |
| 路径 A（无子会话 id） | 按原 item 文案**只重跑该条**，不要重跑整批 |
| 续跑前提 | 必须是**同一会话谱系**（同一条会话里接着跑）；跨会话/换天不能续 |

## 2. 阶段 2 · 分诊（Lead 自己干，不许外包）

- 只读回执的 `outcome=`、`reason=`（失败原因）与正文，挑出**真正需要深挖**的条目（建议 ≤5 条）。
- **`reason` 直接决定动作**（别把所有失败都当一种）：`timeout` / `empty-output` / `provider-error` → 多半可救（续跑或重跑该条）；`attempts-exhausted` → 限流或持续故障，别硬顶；`deadlock` → 批量太大。逐条见 §5。
- **交叉核对是硬要求**：路径 A 的结论只是**线索，不是事实**。任何要进最终结论的断言，必须由你或队友**实证**（读原文、跑命令、查证）后才可引用。
- 正文带未转义标记不用怕：swarm 用**动态围栏**输出，正文原样保留不会破结构；正文里的标记符号不代表工具出错。

## 3. 阶段 3 · 深挖（agent team）

- 一条深挖任务 = 一个队友 + 一个明确交付物（"给我 X 的定义与调用点，附文件:行"）。
- 用 `team_task_create` 建台账；有前后依赖就 `blocked_by`。
- 别把已被证据排除的条目也丢给队友 —— 阶段 2 省下的钱就是这里省的。

## 4. 阶段 4 · 回执（必交，格式固定）

1. **结论**：一句话（附被点名条目清单）
2. **证据**：命令 + 结果（谁验证的、怎么验证的）
3. **未决**：没查清的、以及你没做的（不要用推测填空）

## 5. 失败处理（`outcome≠completed` 的三条路）

| 情况 | 做法 |
| --- | --- |
| `reason=timeout`（超时）或 `reason=empty-output`（空产出） | 有 `agent=` 就**续跑**（接着那个子会话）；没有就只重跑该条（调大 `timeoutMs` 或把提示词写得更聚焦）；仍不行就**降级给队友** |
| `reason=provider-error`（provider/传输报错） | 多半是瞬时故障：只重跑该条；连续两次同一错误再降级 |
| `reason=attempts-exhausted`（重排队用尽预算） | 限流或持续故障，**不要**立刻重发一批去「顶」限流；等一会儿、减批量或减并发 |
| `reason=deadlock`（死锁防护判负：最后一个任务持续限流） | 设计行为。批量/并发太大 → 调小 `maxConcurrency`、`rampLimit` 或切批 |
| `reason=max-tokens`（子代理撞到 token 上限） | 任务的交付物太大：**拆小任务**（一条只问一件事），或调大 `maxTokens`；重跑同样的提示多半还是撞上限 |
| `reason=refusal`（子代理拒绝了任务） | 换个说法/换角度重发，或**降级给队友**（队友能追问和澄清）；不要反复原样重试 |
| `reason=failed`（没给出更具体原因，兜底值） | 先看该条的 `error` 文案再决定；判不出来就当 `provider-error` 处理（重跑该条一次） |
| `reason=aborted`（被取消/中断） | 若不是你主动取消，检查是否触发了批级超时；必要时调大 `toolTimeoutMs` |
| 部分完成 | **只处理未完成的**；已完成条目不重跑（省钱，也避免答案漂移） |
| 前置校验报错（数量/占位符/重复/长度） | 照文案改参**重发一次**；不要改写成逐条调用（那等于放弃扇出的意义） |

## 6. 降级与兜底

| 情况 | 做法 |
| --- | --- |
| 工具列表里没有 `agent_swarm`（插件未装配） | 阶段 1 用 `spawn_teammate` 扇出，或退化为逐条处理；**明确告知用户降级了** |
| 没有 agent team 工具 | 只做阶段 1 + 分诊，把升级候选列成清单交回用户 |
| 限流（429/quota） | swarm 自动挂起重排队（退避 3s×2ⁿ，容量收缩后 180s 恢复）；**不要**自己重发一批去"顶"限流 |
| 需要工具但当前是路径 A | 让实例配 `subagentProvider`（路径 B），或改用队友 —— 不要硬塞给无工具的子任务 |

## 7. 两个可直接照抄的流程

**A. 批量审查（40 个文件 → 2 个队友深挖）**
1. 路径 A 扇出 40 个文件问"风险等级 + 一句话理由"，格式钉死；
2. 分诊出高风险 ≤5 条；
3. 路径 B 或队友对这 5 条做"读原文 + 定位行号"的实证；
4. 回执三段。

**B. 批量调研（12 个主题 → 3 个队友实证）**
1. 路径 A 扇出 12 个主题问"是否需要外部事实核查（是/否）+ 理由"；
2. 挑出"是"的主题；
3. 队友用工具逐条查证（给出处）；
4. 回执三段，未查证的明确写"未决"。

## 8. 收尾自检

- [ ] 我是否**先**用了便宜的扇出，而不是一上来就 spawn 一堆队友？
- [ ] 进结论的每条断言，是否都有**实证证据**（而不是子代理的说法）？
- [ ] 未完成项是**续跑/重跑该条**，还是误重跑了整批？
- [ ] 回执里"未决"部分是否诚实（没查清就写没查清）？
